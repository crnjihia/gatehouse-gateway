Integration & Deployment

        
Developer Quickstart

        
Run Gatehouse Gateway locally or behind your production Kubernetes / Docker Compose topology.

      


      

        

          
          
          
          
        


        
        

          

            Launch the complete production stack (Gateway, PostgreSQL 15, Redis 7, WireMock, Prometheus, and Grafana) with a single command:
          

          
# 1. Clone repository
git clone https://github.com/crnjihia/gatehouse-gateway.git
cd gatehouse-gateway

# 2. Start full 6-container topology
docker compose up -d --build

# 3. Verify health
curl -s http://localhost:8080/actuator/health | jq .
# -> { "status": "UP" }

        


        
        

          

            Onboard new API clients with customized plans, rate limits, and daily quotas using the Admin Master Key:
          

          
# Create new enterprise client
curl -X POST http://localhost:8080/admin/clients \
  -H "X-Admin-Key: gatehouse-master-admin-key-9988" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "Stripe Payments Corp",
    "ownerEmail": "api@stripe.com",
    "plan": "ENTERPRISE",
    "rateLimitPerMin": 6000,
    "quotaPerDay": 1000000
  }'

# Returns raw API key once (hashed with SHA-256 in PostgreSQL):
# {
#   "id": "c71f54a8-6b5e-436f-b258-0097781bcf7b",
#   "name": "Stripe Payments Corp",
#   "apiKeyPrefix": "gh_live_a1b2c3d4",
#   "rawApiKey": "gh_live_a1b2c3d4_8f99e3a...",
#   "status": "ACTIVE"
# }

        


        
        

          

            Authenticate downstream microservice calls using client-specific RS256 JWT bearer tokens:
          

          
# Call protected downstream route
curl -i http://localhost:8080/api/v1/users/42 \
  -H "Authorization: Bearer eyJhbGciOiJSUzI1NiJ9..."

# Propagated to downstream services:
# X-Client-Id: client-enterprise-99
# X-Client-Scopes: [users.read, users.write]
# X-Request-Id: 51bab0d0-5be9-4bb8-b182-a5f363d56f74

        


        
        

          

            Add or update routes in PostgreSQL `route_configs` table and trigger an immediate zero-downtime refresh:
          

          
# Trigger route table reload via Admin API
curl -X POST http://localhost:8080/admin/routes/reload \
  -H "X-Admin-Key: gatehouse-master-admin-key-9988"

# Response:
# {
#   "status": "SUCCESS",
#   "message": "Dynamic route refresh triggered successfully."
# }

        


      

    


    
    

      

        
Telemetry & Monitoring

        
Full Production Observability

        
Micrometer metrics mapped directly to Prometheus and visualizable via pre-provisioned Grafana dashboards.

      


      

        

          
gateway.requests.total

          
Counter metric partitioned by {route, method, status} tracking real-time traffic volume.

        

        

          
gateway.request.duration

          
High-resolution latency histogram calculating p50, p95, and p99 percentiles.

        

        

          
gateway.ratelimit.rejected

          
Tracks 429 quota and rate-limit violations partitioned by {clientId}.

        

        

          
gateway.circuitbreaker.state

          
Gauges tracking Resilience4j state (0=CLOSED, 1=OPEN, 2=HALF_OPEN) per route.
